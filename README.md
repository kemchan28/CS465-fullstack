#Architecture
Looking back from the beginning of the course until now, there has been growth in the knowledge and understanding of the importance of the full-stack project by including Express HTML, JavaScript, and the SPA (Single Page Application). Looking at the formats side by side of all the formats they each have their own benefits and setbacks. In the aspect of utilizing Express HTML it shifts the structural computation burden onto the server; in the aspect of the client making a request, the system would fetch data from the MongoDB database and inject it into the layout template, which would compile it into a flat HTML and would transmit it throughout the system. Conversely, the SPA would download the raw framework, all bundled together. The server would then merely pass the JSON text, therefore leaving the client’s device to draw the actual layouts. Having the JavaScript positioned in the middle to act as a lightweight tool to alter a pre-rendered block on demand. Express HTML has a distinct MPA (Multi- Page Application) by switching navigation entries to prompt a full window flash as the previous page context completely unmounts and wipes state. While looking at SPA, it replaces this with smooth, instantaneous component swapping because of URL modifications without refreshing the tab. JavaScript adds dynamic moments to an MPA architecture, allowing the user to submit small tables asynchronously without retriggering broad window paint. In the Express HTML environment, the application's state is a bit hard to pin down locally inside the UI unless it relies heavily on cookies, local storage, or server sessions since every click reinitializes the document. SPA operates like a continuous desktop program where the app resides natively in application memory safely across countless route adjustments. JavaScript alone is able to preserve a scope inside the immediate lifecycle of that specific layout, and refreshing the document would instantly reset all active script variables. 

#Functionality
Having the backend set up using a NoSQL MongoDB database is to guarantee a flexible data structure, rapid development, and easy horizontal scaling compared to traditional relational databases that lock data into rigid tables and columns. MongoDB stores information dynamically in JSON-like BSON documents. JSON is different from JavaScript and is used to tie together the frontend and backend development components by being a structural bridge between them, using APIs and allowing different systems to communicate with each other. JSON is a lightweight text format that is used to store and exchange data, compared to JavaScript, which is a full programming language that executes the logic. Within the full-stack process, refactoring code was necessary to improve functionality and efficiency by using a direct DB to API where it calls on the client and pulls data to a structured RESTful API endpoint that returns clean JSON. Another thing that refactoring is beneficial for is that it helps extract repeated data-fetching code that is fed into a shared service utility while also operating state management that would replace scattered local variables with a centralized state store. Aside from this, being able to reuse the UI components is also beneficial in the sense that it provides less code by being able to use it across multiple pages. Another thing is the visual match by keeping the same look and style across the application, which also helps by making fixes easy through updates in one file that will change everywhere else, while also having a fast-building setup that makes future development cycles easy to update. 

#Testing
Some of the methods that request and retrieve necessitate various types of API testing of endpoints, in addition to the difficulties of testing with added layers of security. Some examples of these added security layers, such as tokens and encryption, make it a bit harder since it now must pass through extra checks before the server allows access to the data. Breaking down the understanding of methods, endpoints, and security in a full-stack application that implements API testing in security can be shown through the Request method having four commands like GET, POST, PUT, and DELETE, with each of them connecting to the server with data to be edited. Endpoints utilize URL paths with specific web addresses where the client and server can communicate within certain parameters to filter the data from the body, which would then be returned to the client from the server of the data. The security layers used in the class range from tokens, CORS, HTTPS, and Roles that connect to the database for user authentication, with encrypted data and rules in place to stop or block unauthorized users from gaining access to the server.
